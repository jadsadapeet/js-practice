# ฝึกรีวิวโค้ด

แต่ละโฟลเดอร์มีโค้ดที่ "ดูเหมือนใช้งานได้" แต่มี bug และจุดที่ควรปรับปรุงซ่อนอยู่

## ขั้นตอน (ทำตามลำดับ อย่าข้าม)

1. **อ่านโค้ดก่อน ห้ามรัน test** อ่าน `README.md` ของโจทย์ แล้วอ่านโค้ดใน `code.js`
2. **เขียนรีวิว** ลงใน `REVIEW.md` ของโฟลเดอร์นั้น บอกว่าเจอปัญหาอะไร บรรทัดไหน และควรแก้ยังไง
3. **รัน test** ด้วย `npm run test:review` แล้วดูว่ามี bug ที่คุณพลาดไปไหม
4. **แก้โค้ด** จนทุก test ผ่าน

> test จับได้แค่ bug ด้านการทำงาน ส่วนเรื่องอ่านยาก ตั้งชื่อไม่ดี หรือโค้ดซ้ำ test จับไม่ได้ ต้องใช้สายตาคุณเอง

## Checklist ตอนรีวิว

- [ ] **ถูกต้อง:** ทำตามที่โจทย์บอกจริงไหม
- [ ] **Edge case:** ถ้าเจอ array ว่าง, `null`, `undefined`, ตัวเลขติดลบ, `0`, string แทน number จะเป็นยังไง
- [ ] **Mutation:** แก้ข้อมูลที่รับเข้ามาโดยไม่ตั้งใจไหม
- [ ] **การเปรียบเทียบ:** ใช้ `==` แทน `===` ไหม หรือเทียบตัวใหญ่ตัวเล็กผิดไหม
- [ ] **ขอบเขต:** loop หรือ `slice` เกินไปหรือขาดไป 1 ตัวไหม (off-by-one)
- [ ] **ทศนิยม:** คำนวณเงินด้วยทศนิยมแล้วผลเพี้ยนไหม เช่น `0.1 + 0.2` ไม่เท่ากับ `0.3`
- [ ] **อ่านง่าย:** ชื่อตัวแปรสื่อความหมายไหม ใช้ `var` หรือมี magic number ไหม
- [ ] **Error:** ถ้าข้อมูลผิด แจ้ง error ชัดเจนไหม หรือเงียบแล้วคืนค่าผิด ๆ
